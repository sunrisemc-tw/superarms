P1 bugs

2. expire() 誤刪最後一行：改用 PlainTextComponentSerializer 掃描並只刪除含「附魔有效至」的行；找不到不刪其他 lore。若已有「附魔已失效」，不再修改 lore，只補清 EXP；否則只新增一次失效行。
3. Lazy 掃描過重：join 與精準 callback 才走 checkInventory()；use、breakBlock、damage 全部改走 checkMainHand()，只讀寫事件玩家當下主手物品。
4. /superarms <uuid>：找到模板後改為 AdminService.openManage()，不再開玩家商店。
5. buy / shop 權限：buy.permission-required=true 時，/superarms shop、/superarms buy <uuid>、GUI 點擊與最後扣款前都檢查 superarms.buy；無權限直接回 no-permission。

額外修正
- 修正 WeaponRepository.load() 原本以 weapons section 再讀 weapons.<uuid> 相對路徑，導致已存模板欄位讀回預設值；現在以每個 UUID child section 讀取，未知 material 回退 DIAMOND_SWORD。
- WeaponRepository.all() 回傳 snapshot 並同步 load/save/create/remove，避免 Folia 多 entity thread 迭代時 ConcurrentModificationException。
- 經濟 provider 嚴格依 currency 選擇；PlayerPoints 缺少時不會錯誤 fallback 成 Vault 扣款。
- Bukkit NamespacedKey 不允許大寫，PDC expiresAt 的實際 key 改用 superarms:expires_at；Java 欄位與規格語意仍維持 expiresAt。
- 新增嚴格 date/duration parser；錯誤日期（例如 2026-02-30）與 overflow duration 不再被默認成永久/不限。
- 全部本輪新增與改寫 Java 使用正常多行 statement、4-space 縮排；無單行壓縮 if/for。

偏離與原因
- 依本輪要求使用 Chest GUI + Chat prompt，未使用不可用的 Dialog API。
- Minecraft client 無法送出真正的空聊天訊息；程式仍接受空字串，並額外提供 0 / - 作為玩家實際可輸入的「不限」值。
- PDC schema 文件名稱為 expiresAt，但 Bukkit NamespacedKey 僅允許小寫字元，因此實際持久化 key 使用 expires_at，否則 plugin 會在建立 key 時拋 IllegalArgumentException。
- 本機沒有可啟動的 Canvas/Folia 測試伺服器，因此未做真人 GUI 點擊測試；以 Folia API 1.21.11 編譯、JUnit 與 holder/事件路徑靜態檢查驗證。
